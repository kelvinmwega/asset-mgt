## Goal

Every dropdown in the app opens one in-app panel — the same trigger, width rule, height rule, focus ring, tick and empty-choice wording in light and dark — instead of the OS picker. The person picker is searchable by name or employee ref and opens inline in its dialog on phones; "More" closes on Escape. Every form still posts the same `FormData` to unchanged server actions.

## Acceptance criteria

Copied from the PRD story, or written here if ad-hoc. These are what the `reviewer` checks the diff against. Every criterion carries an id the task table cites: `AC<n>` for story criteria, `G<n>` for design-spec guards, `I<n>` for tech-spec invariants, `C<n>` for advisor conditions. A criterion is every line indented beneath it, up to the next `- [` line or a heading, and `plan-to-args` reads them all into its text. An indented `-` or `*` bullet joins with `; `, its `[ ]` or `[x]` marker dropped, so the launch record holds `<lead>; <first>; <second>`. An indented line that is not a bullet is the line above it wrapped, and joins with a space. A blank line does not end the criterion: an indented paragraph after one joins with `; `, as do the bullets under it. A `;` at the end of a clause is not doubled by the join. Any other line after a criterion is read into none — a line that is not indented, a checkbox line out of the criterion shape, a fenced block — and `plan-to-args --strict` refuses the plan, naming the criterion and the line; without `--strict` it warns. Label a group of criteria with a `###` heading, which ends the criterion above it: prose under a heading, like prose before the first criterion, is never read and never refused. A tag may sit between the bold id and the dash, as `_(…)_`, `*(…)*` or `(…)`, and stays at the front of the text. No table cell may hold an unescaped pipe: a criterion quoted into a cell writes a literal pipe as `\|`, or the row splits there.

Copied verbatim from `DESIGN-SPEC.md` § 7.

- [ ] **G1** — No native `<select>` element is rendered as a visible, interactive control anywhere in `src/app` or `src/components`; every dropdown is the shared Select, Combobox or Menu. Fails when someone adds or keeps a raw `<select>` (or the old `select.tsx` primitive) at any call site.
- [ ] **G2** — Every Select and Combobox submits its value through `FormData` under the same `name` as today, so every server action receives byte-identical input. Fails when someone drops the hidden form input, renames a field, or moves a value into client state only.
- [ ] **G3** — A Select or Combobox trigger is always the full width of its wrapper; no trigger width depends on its options. Fails when someone puts `w-fit` (or an option-length-driven width) back on a trigger.
- [ ] **G4** — On a coarse pointer every form control is at least 44 px tall: `Input`, `Button`, Select and Combobox triggers, the picker's search field, and every option and menu row. Fails when someone fixes a control or row height in px without the coarse-pointer variant, or applies it to the dropdowns alone.
- [ ] **G5** — Empty choices use exactly four phrases, each with one meaning: "Any <noun>" (filter with no constraint — the register's Category and Site filters), "Not recorded" (optional attribute left blank — Condition, Site; the asset form's "Unassigned" becomes "Not recorded"), "Leave unchanged" (repair dialogs), and a "Choose a <noun>" placeholder that is never an option (required, no default). Fails when someone ships "All", "Unassigned", "None" or a disabled placeholder option.
- [ ] **G6** — The asset form's required Category starts empty on create and cannot be submitted empty; nothing is preselected for the operator. Edit still opens on the asset's category. Fails when someone restores a first-option default.
- [ ] **G7** — The person picker filters on a case-insensitive substring of name OR employee ref, reports the visible count politely to assistive tech, and shows "No one matches "<query>"." with a Clear search action when empty. A person without an employee ref shows nothing in the ref column, except that when their name appears more than once in the visible list the ref-less row shows a muted "No ref". Fails when someone filters on name only, prefix-matches, reintroduces "no employee ref" on every row, or lets two same-named, ref-less rows render identically.
- [ ] **G8** — The person picker is fed exactly the `people` prop it receives today; no new query, field or role reaches it. Fails when someone fetches or widens person data for the Combobox (§ `STAFF_RO`-sees-no-person-data; `personSelectFor` is untouched).
- [ ] **G9** — A popup opened inside a Radix Dialog renders above it, keeps focus inside the dialog's trap, and Escape closes the popup first without closing the dialog. Fails when someone portals the panel outside the dialog's layer or lets Escape propagate.
- [ ] **G10** — Escape and outside click close the "More" menu and return focus to its trigger; choosing an item opens that move's dialog, and closing the dialog returns focus to "More". Fails when someone nests the dialog inside the menu content so it unmounts when the menu closes.
- [ ] **G11** — The moves a status offers stay assertable in tests: the AM-03 lifecycle tests keep asserting which moves each status renders, adapted to open the menu first, and keep failing when a move is wrongly offered. Fails when someone deletes or weakens those assertions to make the menu change pass.
- [ ] **G12** — Secondary text in a highlighted row (employee ref, a muted empty choice) meets 4.5:1 in both themes. Fails when someone leaves `--muted-foreground` on the `--accent` fill.
- [ ] **G13** — A required Select or Combobox left empty shows the app's invalid state and inline message, never a browser validation bubble anchored to a hidden element. Fails when someone relies on native `required` on the hidden form control for the error UI.
- [ ] **G14** — With `prefers-reduced-motion: reduce` the panel opens and closes without transform or fade. Fails when someone adds an animation without the reduced-motion variant.
- [ ] **G15** — An empty choice ("Any …", "Not recorded", "Leave unchanged") reaches the server exactly as today's empty `<option value="">` does, and an optional column it writes lands as `NULL`, never `''`. Radix `Select.Item` rejects `value=""`, so the empty choice carries a sentinel that is mapped back at the form boundary. Fails when someone lets the sentinel string reach a server action, or writes `''` where today's path writes `NULL` (the `Asset.tag` / `Person.email` trap in CLAUDE.md).
- [ ] **G16** — Below 640 px the person picker renders its search field and list inline in the dialog body, with the list height capped to the visible viewport, so Cancel and Assign stay reachable with the soft keyboard up. Fails when someone ships the floating panel at phone width or lets the list push the actions off-screen.
- [ ] **G17** — Select panels use `position="popper"`: below the trigger, at least its width, flipping near the viewport edge. Fails when someone keeps shadcn's `item-aligned` default, which overlays the trigger and breaks the mockup's anchoring.
- [ ] **G18** — The person picker's filtering and listbox semantics come from `cmdk` (shadcn `Command`): the search field owns `role="combobox"`, `aria-controls` and `aria-activedescendant`, and arrow keys move the highlight without leaving the field. Fails when someone hand-writes the listbox or puts the combobox role on the trigger button.

A literal pipe inside a cell is written as a backslash-pipe (`\|`); a row splits only on unescaped pipes. `ACs` cites the ids above that the task satisfies — every cited id must exist. Each claim a row or the plan makes about a binary, an API or a log line is marked `measured` (read off the thing itself) or `assumed` (from its docs, a default or memory), and a measured figure is written as value · window · stamp — the figure, the samples or configuration it was computed over, and the commit or `date -u` time it was read at (`process/measured-figure-names-its-window`). ## Test approach

- **New/changed tests:** primitive tests (row 1) open each control with userEvent and assert roles, posted `FormData`, the sentinel never reaching it (G15), the invalid state without a browser bubble (G13), Escape layering inside a Dialog (G9), cmdk filtering and "No ref" (G7, G18) and the reduced-motion classes (G14). Call-site tests assert the posted names and values per form (G2) and the empty-choice phrases (G5). The AM-03 lifecycle assertions keep their claims, with only the selector changed (G11).
- **Falsifiability:** each guard is red-proved by deleting the production line it defends (CLAUDE.md, Process): the sentinel mapping, `position="popper"`, the coarse variant, forceMount, the hoisted dialog, the repeated-name rule, the eslint rule.
- **Layout and focus** (G3, G4, G9, G16, G17) are proved in a real browser at 1280 and 390 against `mockups/*.html` (`testing/jsdom-cannot-model-layout`); screenshots are never committed.
- **Local scope (T2):** typecheck and targeted tests per task. The full suite, real-DB integration included, runs in CI.

## Delivery record

Written by `/ship` at the end of each launch, every line below by the record generator and never by hand: `node "${CLAUDE_PLUGIN_ROOT}/skills/ship/scripts/delivery-record.mjs" <launch|spend|task|post-wave|decision> --plan <this plan> …`, with each call's flags in `/ship` § 4 steps 6 and 7. `launch` writes the heading and the launch line, `spend` the Spend, Phases, Refutations and Overspend lines, `task` a task's line and its bullets, `post-wave` the post-wave lines and `decision` an operator decision. Task rows above are never edited; only their Done cell is ticked. Every date and time written here comes from `date -u` and carries a `Z` (`date -u +"%Y-%m-%dT%H:%M:%SZ"`) — never local time, never from memory; the generator stamps from the system clock and refuses a stamp without the `Z`. The factory meter (`factory-metrics.mjs`) reads the line shapes below verbatim, and the generator fills them from the meter's own lists; a fact written in other prose reads `unmeasured`.

- `### Launch <k> — run <run id> (<launched> → <returned>)` — a heading opening each launch's entry, both times from `date -u`, the second taken when the result arrives; the wave's wall-clock. The launch line follows it.
- `Spend (workflow output tokens): <spent> of <budget> — money figure: /usage` — the § 6 spend line verbatim. For a run paused or killed before its result, the same line from its last spend checkpoint with `(checkpoint <phase>)` appended, or `Spend: unmeasured — run <run id> stopped before a readable checkpoint`. Only lines of exactly the first shape are summed into the next launch's story spend.
- `Phases (output tokens): Orient <n> · Implement <n> · Review <n> · Fix <n> · Verify <n> · Report <n>` — from the result's `outputTokens.byPhase`, with `Refute <n>` after Review at T3. The story-spend sum does not match this shape.
- `Refutations: <findings> blocking findings put to <refuters> refuters · <refuted> refuted · <upheld> upheld · <abstained> abstained · code <code> · prose <prose>` — at T3 only, from the result's `refutations`; the refuter yield the factory meter reads, with its abstained refuters and findings by kind. `<refuters>` is the count each finding was put to, never a total across findings; `<abstained>` counts the refuter calls that returned nothing; `code` and `prose` count the findings by the reviewer's `kind` tag. A result written before these counts existed writes the line stopping at `<abstained> abstained` or at `<upheld> upheld`, and the meter reads the missing measures as `unmeasured`. A resume from the run id, which only an all-serial plan takes, replaces the earlier launch's line, because on any resume the script recounts every task that reaches Refute, from cache or not — where the cache misses, the earlier launch's refuter work for that stage leaves the yield; a launch rebuilt with `--undone` adds its own.
- `**Task <n>** — <commits>; fix rounds <rounds>; regression round <ran|not run>; open findings: <findings>` — one line per task, `<rounds>` the fix rounds it ran inside the wave (`0` when its first review approved) and `<ran|not run>` the literal `ran` or `not run`; beneath it the verification record and every `needsRatification` entry (<decision> — <why>). A regression round is recorded on this line alone, with whatever stayed open after it in its `open findings` — never on a separate line, which the meter would count as a second round.
- `Post-wave round <k>: <commit> — <findings answered> — reviewer <verdict>` for every round after the wave. Until one runs, `No post-wave round ran`, replaced by the first numbered round — never a `Post-wave round 0:`.
- `Operator decision (<at>): <decision> — <why>` for every call the operator makes during the story, the one after the second post-wave round included; `<at>` from `date -u`.
